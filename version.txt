1.10.0
- Security Hardening & Endpoint Access Control: Restricts `/monitoring`, `/admin/ldap`, `/sso-inspect`, `/docs`, and `/swagger` strictly to administrators (`DAI_ADMIN`, `GATEWAY_ADMIN`, or role `ADMIN`)
- Administrative API Protection: Enforces `@admin_required` server-side authorization on `/api/v1/ldap/*`, `/api/v1/sso/inspect`, `/api/v1/housekeeping/*`, and `/api/v1/openapi.json`
- Dedicated 403 Forbidden Access Denied UI (`app/templates/403.html`): Displays user identity, required entitlement, and direct return-to-dashboard navigation
- OWASP Security Response Headers: Automatic injection of `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `X-XSS-Protection: 1; mode=block`, `Referrer-Policy: strict-origin-when-cross-origin`, and `Content-Security-Policy` across all responses
- Secure Session Cookie Flags: Enabled `SESSION_COOKIE_HTTPONLY = True` and `SESSION_COOKIE_SAMESITE = "Lax"`
- SSO Header Sanitization: Strips CRLF (`\r`, `\n`), null bytes, and non-printable control characters from extracted headers and group memberships to prevent header injection and log tampering
- Security Audit Logging: Unauthorized access attempts trigger `ADMIN_ACCESS_DENIED` events with `status="DENIED"` recorded in `logs/audit.log`
- Comprehensive Test Suite & Documentation: Added `tests/test_security_hardening.py` (25 automated tests), authored `docs/SECURITY_TESTING_GUIDE.md`, and updated `Testing_features.md` with Module 10

1.9.0
- Added operational `mode` configuration setting (`"local"` vs `"production"`) in `config/gateway.yaml` and `config/gateway.sample.yaml` (with support for both `.yaml` and `.yml` extensions)
- Standalone local mock mode design: completely bypasses PostgreSQL database connection pooling, table creations, sessions, and queries via `MockDatabaseManager`
- Safe local execution: resolves local setup startup failures where PostgreSQL is absent, allowing the application and LDAP admin page (`/admin/ldap`) to load instantly with in-memory mock data
- Local mode API guarding: functional and downstream APIs (`/api/v1/*`) are disabled with HTTP 503 mock responses while telemetry (`/api/v1/heartbeat`) and OpenAPI schema (`/api/v1/openapi.json`) remain operational
- Global mock warning banner: rendered across every UI page (`/`, `/dashboard`, `/admin/ldap`, `/monitoring`, `/sso-inspect`, `/docs`, `/swagger`, `/execution/*`): "Warning: This is a mock page and API / etc won't work."
- UI header indicators: added `LOCAL MOCK MODE` badge and updated heartbeat status pill to display `Local Mock (Alive)`
- Preserved production mode: when `mode: "production"` is configured, full live PostgreSQL, LDAP, and execution API connectivity operate as standard
- Comprehensive automated test suite `tests/test_local_mode.py` covering configuration parsing, database bypass, warning banner rendering, API guard, and production mode preservation

1.8.0
- Independent LDAP directory synchronization worker with RFC 2696 paged searches, SSL/TLS, and Active Directory attribute mapping
- Dedicated directory configuration in `config/ldap.yaml` and reference sample in `config/ldap.sample.yaml`
- PostgreSQL schema expansion with `gateway_users`, `gateway_ldap_groups`, `gateway_user_group_membership`, and `gateway_ldap_sync_status` tables
- Single Sign-On (SSO) decoupling: extracts UID from `header_user` (e.g. `X-Remote-User`) and resolves entitlements from local PostgreSQL in <1ms
- Option A Just-In-Time (JIT) fallback for instant on-the-fly synchronization of unsynced users upon first authenticated login
- PostgreSQL session-level advisory locking (`pg_try_advisory_lock`) preventing race conditions across multi-node ALB clusters
- Dedicated structured logging architecture for LDAP operations: outputs to `logs/ldap.log` and mirrors to `logs/service.log`
- Admin Management Dashboard (`/admin/ldap`) with real-time health metrics, on-demand sync triggering, entitlements explorer, live YAML configuration editor, and embedded live LDAP log stream
- Standalone CLI runner `scripts/sync_ldap.py` with `--test`, `--dry-run`, and `--user` support with structured JSON logging for scheduled cron execution
- REST endpoint `GET /api/v1/ldap/logs` for real-time administrator log monitoring and audit
- Dedicated LDAP operational and configuration guide (`docs/LDAP_SYNCHRONIZATION_GUIDE.md`)
